## 検証のしかた（これが土台）

スクリプトは **`unity/tools/`** にある（セッションのスクラッチパッドに置くと次回消える）。

```bash
powershell -File natsuyasumi-hld6gbpixy5rsx/unity/tools/rebuild.ps1
```

- `rebuild.ps1` … 場面＋Windowsプレイヤーを組む。`-Web` で WebGL も。`-Only Paths` などで単発実行。
- `shot.ps1` … 組んだ実行ファイルを引数つきで走らせて絵を撮る。主な引数はファイル先頭のコメント参照
  （`-tod` `-clock` `-at x,z[,y]` `-cam d,pitch,yaw` `-bugs` `-sumo` `-play` `-face` `-pose` `-run` `-walkhold`）。

**見た目の確認は必ず実プレイヤーのビルドで撮る。** エディタの batchmode 描画は嘘をつく。

**自動運転は「上手に遊ぶ」ようにする**（`PlayHost.debugAuto`）。一定間隔で押させると
水切りは毎回0段・釣りは毎回逃げられ、**成功したときの画が一度も撮れない**。

**ビルド中にファイルを編集しない。** Unity が途中で再コンパイルして
「アセットが書けない」という無関係に見えるエラーで落ちる。

## 地形（いちばん事故が多い）

- **絵を見ても高さは読めない。`rebuild.ps1 -Only Paths` で数値を出してから置き場所を決める。**
  1mごとの傾斜、道の横の段差、家まわりの高さが出る。地形を触ったら必ず回す。
- **道は「1本ずつ」ではなく「網としてまとめて」解く**（`TerrainGen.EnsureProfiles`）。
  道ごとに独立して高さを決めると、枝道の起点が本道の削った高さでなく素の地形から始まり、
  辻が崖になる（実測72度で歩けなかった）。
  手順：1mごとに刻む → 素の地形へ弱く引きもどす → 少しならす → 勾配上限 → **辻をそろえる（必ず最後）**。
  引きもどしを強くすると辻の処理と収束せず崖が戻る。辻とみなす半径は 0.4m（広いと無関係な点が結ばれる）。
- **勾配上限は道ごと**（`PathGrade`）。谷そこ 0.10〜0.12（6〜7度）／山道のみ 0.26。
  **本人の言：歩く道に極端な角度はない。家のまわりは5度、最大でも10度。**
- **削る幅も道ごと**（`PathCut`）。狭いと急斜面で両側が壁のまま残り、溝の底を歩くことになる。
  本道9m・枝道5m・山道12m。土の色がつく幅は別（`PathHalfPer`）なので道すじは細いまま見える。
- **谷そこは四角く広く**（`FlatCenter`/`FlatHalf`）。円だと家の前の道に届かず、道が山ぎわの
  高さに引っぱられて家の前が3m浮いた（玄関が二階の高さになった）。
- `Mathf.SmoothStep` は GLSL の smoothstep **ではない**。正規化したいなら自前で書く（`SmoothBand`）。

## カメラ

- ふだんは **正面固定（yaw 180）**。自由に回せる機能は無い。
- **回すのは 90度きざみだけ**（`CamOrbit.Zone`）。180度回すと押したキーの行き先が裏返って操作しづらい。
  180度が要る所は**道を直角に2回曲げて 90+90 にする**（山道がその例）。
- **キーを押しているあいだは入力を読みかえる向きを変えない**（`PlayerMove.basisYaw`）。
  押しっぱなしならカメラが回ってもそのまま進む。手を離すと今の画面にそろう。
- ゾーンには `fogScale` がある。遠くを見せる所は薄くしないと灰みどりに溶ける。
- **カメラは地面より下に潜らせない**（`groundClearance`）。ただし持ち上がると構図が変わるので、
  そもそも潜らない置きかたにする（棚は奥ゆきを深くとる）。

## 見た目

- 色は **木立ち(ansimuz CC0)から吸いだした20色**にそろえる。
- **ドットのこまかさは 1mあたり32ドット**（木＝144pxを4.5mに貼っている）。
  ここを外すと「テクスチャ貼ってる？絵っぽくない」になる。壁は1タイル1.5mなので48px。
- 写真素材を使うときは **一部だけ切りとって**縮める。全体を潰すと模様が消えてただのノイズになる。
  模様が大きいものほど大きく切りとる。色数も7〜8まで落とす。
- **テクスチャを足したら `rebuild.ps1 -Only Pixel` を必ず回す。**
  新規ファイルは既定のバイリニア＋圧縮で入るので、上書きしたものだけ点フィルタが効いて
  「同じ作業をしたのに数枚だけぼやける」が起きる。
- 主人公は魔理沙の8方向×8状態（`marisa_8x8.png`）。向きは**カメラから見た向き**で決める。
  世界の向きだとカメラが回った瞬間に「画面の右へ歩いているのに左を向いた絵」になる。
- **主人公のまわりだけ手前の物を抜く**（`SeeThrough.cs` + PixelSprite の `ClipHole`）。
  主人公より手前にある物だけ抜く。虫など抜かれると困るものは材質に `_HoleIgnore` を立てる。

## 建物（家・納屋・小屋）

- **「絵が貼ってあるのに箱に見える」ときは、絵ではなく形を疑う。** 家がずっとそうだった。
  屋根＝傾けた箱2まい（棟がなく空がすける／妻が開けっぱなし／反りがない／軒が板1まいの厚み）、
  壁＝地面から軒まで一様な面。これはテクスチャをいくら良くしても直らない。
- **建物は「面を張る」のではなく「役目のちがう部品を組む」。**
  隅柱・軒の出・けらば・破風板・軒の小口・軒天・垂木・腰壁・水切り・貫・窓のわく・桟。
  立体に見える理由はテクスチャではなく、**この凹凸が影を作ること**。
- **入母屋のメッシュは「輪(リング)を積む」で組める**（`Assets/Editor/HouseRoof.cs`）。
  高さ t ごとに四角い輪を作って輪どうしを面でつなぐ。奥ゆきは棟で0まで縮め、
  横は隅棟の位置で**縮むのを止める**。止めた先は x が動かず y だけ上がる＝そのまま妻壁（垂直）。
  入母屋の「寄棟＋切妻」は、縮みかたを途中で止めるだけで出る。
  反りは `Y(t)=yEave+rise*t^1.34`（棟がわが急・軒がわがゆるい）、軒先は `t²` で少しはね上げる。
- **面をまわす向きをまちがえると裏返る。** 裏返った屋根は上から見ると軒天（板）が見え、
  **瓦のはずが茶色い板になる**。庇と下屋だけ木の色に見えたらこれ。
- 屋根のメッシュに**当たりをつけない・層は2(Ignore Raycast)**。真下へのレイが屋根を地面と
  見なして虫が空中に湧く（`Invisible` と同じ事故）。
- 外がわに貼る化粧板（腰壁・柱・貫）は**当たりを外す**。壁より12cm外に出るので、
  当たりを残すと家のまわりがふくらんで沓ぬぎ石に乗れなくなる。
- 日本の民家の壁は「白い面」ではなく**「木の枠にはめた白い面」**（真壁づくり）。
  腰は下見板、上は漆喰、あいだに水切り。柱は1間（1.8m）ごと。
- **屋根を上げたら壁も上げる。** 土間の上を吹きぬけにするなら外壁を軒げたまで通す。
  忘れると壁の上が素どおしになって外から家の中が見える。

## マテリアルの貼りかた（見落としやすい地雷）

**箱の UV はどの面も 0〜1。** つまり同じマテリアルを 10.8m の壁と 0.6m の壁に貼ると、
**絵のこまかさが18倍ちがう**。下見板を 10.8m の腰壁に貼ったら板のすじが1本も出なかった
（絵1まいが 10.8m に引きのばされた）。

→ `BuildZashiki.FitMat()` が面の大きさ(m)を受けて **1.5m＝絵1まい**（48px÷32px/m）に
そろえたマテリアルを返す（同じ大きさは使いまわす）。壁・板を置くときは必ずこれを通す。

→ **メッシュで作ったものは UV に m を焼きこむ**ので、貼りかたが `(1,1)` の別マテリアルが要る。
箱用の `(7.2, 1.6)` をわたすと絵が7倍にのびてただの灰色になる。

## 借りものの 3Dアセットを つかう（megakit）

`unity/ArtSource/ref/` が 手本置き場（Unity の 外・gitignore）。使う ぶんだけ
`make_megakit.py` で `Assets/Art/Models|Textures/megakit/` へ うつす。
したくは `MegaKit.Setup`、寸法は `MegaKit.Dump`、でかすぎる ものさがしは `MegaKit.Inspect`。

- **手さぐりで 組まない。地形と 同じで まず 数字を 出す**（`MegaKit.Dump`）。
  部品の 大きさ・軸の 位置・向きが 分からないと 置いた とたん 半分 めりこむ。
- **Quaternius のキットは ねている。** 高さが -Z、厚みが Y、外がわが -Z。
  置くときに `Euler(0,yaw,0) * Euler(90,0,0)`。手前(+Z)を 見せる 面は yaw=180。
- **prefab の 根っこに 100倍が 入って いる。置くとき `localScale = Vector3.one` に もどす。**
  忘れると 壁 1まいが 200m x 312m に なって 画面ぜんぶを 覆う。
  このとき `Dump` は 2.00m と 出て いた——**測るときに scale を 1 に 直して いたから**。
  **測るときと 置くときで 条件を そろえないと、正しい 数字が 嘘に なる。**
- **`SetupURP.FixPixelArt` の 対象外に する**（`/megakit/` を はじく）。
  1024px の 描きこんだ 絵を 点フィルタ＋圧縮なしに すると ざらざら＋ビルドが ふくらむ。
- 法線は「Normals Godot-Unity」の ほうを つかう（素の ほうは Y が 逆で 凹凸が 裏返る）。
  `textureType = NormalMap`、あらさ・ORM は `sRGBTexture = false`。
- FBX は `materialName = BasedOnMaterialName` + `materialSearch = Everywhere`。
  **こちらで 作る マテリアルの 名まえを FBX の 中の 名まえと 1字も ちがえない**（`MI_Plaster` など）。

## アトラス（1枚に コマを ならべた 絵）

- **コマの ふちは 半テクセル 内がわへ 寄せる。** 1/8 ちょうどで 切ると、はしの 1列で
  計算の まるめが となりの コマに はみ出し、**別の 絵が すじに なって 出る**。
  実例：`marisa_8x8.png` は **どの 行も 絵が セルの 下端ぴったり**まで 入って いる
  （下あき 0px）ので、走りの 行の 足もとに 次の 行(喜)の 帽子が にじんで いた。
  → `CharSprite.Set` で `1/Cols - 1/w`、offset `+0.5/w`。
- コマを 足す・アトラスを 作りなおす ときは **上下左右に 1px 以上の あきを とる**。
- 点フィルタでも 起きる（サンプル位置の まるめの 問題で、にじみ方の 問題では ない）。
- ★本すじの 直しは **Unity の Sprite Atlas に 移す**こと。手で UV を 計算するのを やめる。
  そのときは 絵の 作りなおしも いる（PLAN の C1）。

## カメラが 物に じゃまされる とき

3Dゲームで つかわれる 手は 4つ。**この 企画は 1と3の 合わせ技＋2**。

1. カメラと 主人公の あいだの 物を 消す／すかす
2. **当たったら カメラを 手前に 引き寄せる**（Cinemachine の Deoccluder。`CamOrbit` に 実装）
3. **ディザ(市松)で 穴を あける**（`_HoleParams` + `ClipHole`。PixelSprite と DitherLit）
4. 屋内は べつの カメラ・べつの 見おろしに 切りかえる（母屋の `RoomCutaway`）

**★3 だけでは 足りない。** ディザは「カメラと 主人公の あいだに 壁が ある」ときにしか
効かない。**カメラ そのものが 壁の 中に 入ると、壁は ニアクリップの 向こうで 描かれず**、
画面が 家の 中の べつの 面で うまる。そこは 2（引き寄せ）でしか 直らない。

引き寄せは **近づくのは すぐ・はなれるのは ゆっくり**。逆に すると 柱の わきを 走る たびに
カメラが がくがく 前後する。見えない かべ・屋根は 層2 なので 拾わない。

## 当たり判定（あたり）の 決まり

★**本人の 指摘（2026-08-16）：「当たり判定は 先に 物に つけて おいて、それを 配置する
んじゃない？ 全部 同じ 当たり判定 1から って 実装も テストも 無理だよ」。そのとおり。**
いまの 作りは 建物ごとに 手で 箱を ならべて いて、これは 続かない。

**一般的な やりかた（3Dゲームの ふつう）**

1. **あたりは 物(prefab)の 側に 1回だけ つける。置くときは 何も 考えない。**
   同じ 家を 20軒 置くなら、あたりを 書くのは 1回。ここが 崩れると 20倍 テストが 要る。
2. **見た目の メッシュと あたりの 形は 分ける。**（collision mesh／proxy）
   見た目は 何万ポリでも、あたりは **箱・カプセル・球の 数個**。
   MeshCollider は 重く、しかも convex でないと 動く 物に つかえない。
3. **層(Layer)で 用途を 分ける。** 歩く あたり／カメラの あたり／攻撃の あたりは 別物。
   Physics の 行列で「どの 層と どの 層が ぶつかるか」を 決める。
   この 企画では **層2(Ignore Raycast)** を「真下への レイに 出てこない もの」に つかって いる
   （屋根や 見えない かべを 地めんと 見なして 虫が 空中に わく 事故を 防ぐ）。
4. **床は あたりを つけない で すむ なら つけない。** 地形の あたり 1枚で すます。
   建物の 中も 地面と 同じ 高さなら、床の あたりは 要らない。
5. **戸口は「壁を 4枚 置いて まん中を あける」。** まるごと 1個の 箱で かこむと
   **入れなく なる**（実際 やった。本人「部屋の中に入れない」）。
6. **通れない ときは まず「地形か 物か」を 切り分ける。**
   `TerrainProbe.What` が 1mごとに 高さと **そこに ある コライダーの 名まえ**を 出す。
   実例：高台へ 行けない のを「小川の せい」と 見て いたが、じつは 見えない かべ
   `T1_L` が **たまたま 小川と 同じ x=-22** に 立って 曲がり角を 4m ふさいで いた。
   絵を 見て 当てに いくと まず 外す。

**このリポジトリの 現状（正直に）**
- FBX には あたりが **入って いない**（Quaternius のキットも 同じ）。`addCollider=false` で 読み、
  `MegaKit.Hit` で 手で 箱を 置いて いる＝**上の 1 が できて いない**。
- 直すなら「部品ごとに あたり つき prefab を 1回 作り、置くのは その prefab」に する。

## 本番へ 出す（push が 403 に なる）

**このマシンには GitHub の 認証が 2つ ある。**

- `C:/Program Files/Git/etc/gitconfig` … `credential.helper = manager`（Windows 資格情報マネージャー。
  ここに **takashi-nakaya** が 入って いて、この人は org のリポジトリに **書けない**）
- `.git/config` … `credential.helper = store` （`~/.git-credentials` に **petit-game-ailabo**）

helper は **上から 順に 全部 聞かれる**ので、先に manager が 答えて しまい
`Permission to petit-game-ailabo/games.git denied to takashi-nakaya` で 落ちる。

直しかた（**空の値は それまでの helper を 打ち消す**）:

```
git config --local --replace-all credential.helper ""
git config --local --add credential.helper store
```

`deploy.ps1` でも push できるが、**STEP2 で day22 の 動画を YouTube に 上げに いく**ので
なつやすみの ときは 走らせない。
