このファイルが **作業の唯一の台帳**。セッションが切れても、ここを読めば続きから再開できる。

## 回しかた（自動）

毎時ジョブが1回発火するたび、**未着手のいちばん上を1つだけ**やる。

1. この表の `[ ]` のいちばん上を見る
2. 実装する
3. **触った箇所に関係する検査だけ**流す（全部流すと18分かかる。期の区切りでだけ全部流す）
4. commit / push
5. `[x]` にして、**その行の下に1〜2行で結果**を書く
6. 判断をしたら `DECISIONS.md` に追記する
7. 借り物を使ったら `REPLACE.md` に追記する
8. **止まる**（次の発火を待つ）

期（第N期）が全部 `[x]` になったら、その期の締めとして：

- 検査を**全部**流す
- **照合サブエージェント**を1体出して、`DESIGN.md` と実装のズレを見てもらう
- 次の期の中身を組み直してから進む

## 齟齬の判定ルール

調査サブエージェントは「ぼくなつと違う＝不備」と報告してくる。だがこの作品は
**意図して違えている**ところがある（東方キャラ／1画面＝1枚の写真／会話は尽きたら二度と開かない）。

- **ぼくなつ調査は「何が足りないか」の材料としてのみ使う**
- **`DESIGN.md` が「何を意図して違えたか」の唯一の正**
- DESIGN.md と矛盾する提案は**却下**し、却下した理由を `DECISIONS.md` に残す

# 第2期：イベントの仕組み（ここが要望の核）

「ある日ある場所を訪れたら、その日の晩ごはんや翌朝の朝ごはんで会話が起き、
その結果 納屋に釣り竿が置かれる」を、**データだけで書けるようにする**。

- [ ] **B1. 条件とひきがね**
      `when:{ day, place, flag, item, phase }` × `on:'enter'|'talk'|'meal'|'sleep'|'dusk'`
- [ ] **B2. 予約（いちばん大事）**
      いま起きたことが**あとで効く**仕組み。`later:{ at:'dinner'|'breakfast'|'day+2', do:[...] }`
      → 訪れた記録が、その晩の食卓の会話として回収される
- [ ] **B3. 結果**
      フラグを立てる／**物を置く**（納屋に釣り竿）／NPCを出す・消す／会話を解放する
- [ ] **B4. 食卓を毎日の器にする**
      朝ごはん・晩ごはんを「予約された会話が流しこまれる場所」にする。
      いまの `morningScript` をこの器の上に載せかえる。
