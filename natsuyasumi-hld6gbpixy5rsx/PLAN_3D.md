「はりぼてで面白くない・カメラもおかしい」を、買ってもらえるクオリティまで持っていくための計画。
土台になる学びは4枚のスキルに書き起こした（一次資料つき）：

| スキル | 中身 |
|---|---|
| `.claude/skills/3d-game-basics/` | BotWの引力・三角形の法則・ものさし／Neskyのカメラ設計／箱庭思想 |
| `.claude/skills/bokunatsu-design/` | 綾部和の設計思想＋固定カメラ・walkmesh・入力ラッチの技術構成 |
| `.claude/skills/hd2d-look/` | オクトパストラベラー式の絵作り（舞台照明・DoF・Bloom・解像度の罠） |
| `.claude/skills/3d-to-2d-toon/` | ギルティギアXrd式の3D→2D（法線編集・コマ打ち・背面法） |

## 1. 診断：学んだ原則と いまの奥行き版の突き合わせ

| 原則（出典） | いまの状態 | 差 |
|---|---|---|
| **1画面＝一枚絵として成立する構図**（綾部：カメラとレイアウトは本人が直接作る。小津の構図） | 追従カメラ＋90度ゾーン。構図は「設計」されていない | ★最大の差。「カメラがおかしい」の正体はこれ。カメラが絵を作っていない |
| **動的三人称は最難関。単純な方式を恥じるな**（Nesky） | 中途半端に動的（追従） | 固定寄りに振り切る余地。入力ラッチ（basisYaw）は既に正しい実装 |
| **舞台照明のようなスポットライト**（HD-2D：画面の薄っぺらさはこれで消す） | 平らな昼光1灯のみ | ★「はりぼて感」の正体の半分。光が絵を作っていない |
| **深めのDoF＋Bloom＝思い出補正**（HD-2D） | ポストFXほぼ無し | 未着手。Volumeを足すだけで効く |
| **地形は三角形。常に何か目標が見えている**（BotW） | 谷＋道＋家。遠くの目標が見える設計なし | 高台はあるが「登ると次が見える」連鎖がない |
| **引力で誘導**（BotW：行くと得する場所＋変わり種） | 遊び場は多いが「遠くから見えて引っぱる」形になっていない | 配置の問題。物はある |
| **キャラがライトを受ける**（HD-2D／ライブアライブ） | ドット絵スプライトは無反応（常に同じ明るさ） | 夕方・屋内で浮く原因 |
| **ちょっと足らない密度・失敗なし・日記**（綾部） | 31日ループ・絵日記・相棒・大会まで実装済み | ◎ここは先行してできている。この計画では触らない |

**結論：ゲームデザイン（31日の中身）は進んでいる。負けているのは「カメラ＝構図」と「光」。**
この2つは幸い、地形や遊びを作り直さなくても直せる。

## 2. 方針の柱（3本）

### A. カメラを「構図」に振り切る（ぼくなつ式＋Nesky）

- ゾーンごとに**固定カメラ（見せ場の構図）**を設計する。いまの「正面固定＋90度きざみ」を
  「**場所ごとに1枚の絵として設計されたカメラ**」に格上げする。
- 順番が大事：**カメラを決めてから、その絵のために地形・物の配置を動かす**（綾部：窓からゴンドラが
  見えるアングルのために山を動かす／Nesky：カメラとレベルは同時に設計）。逆をやっていたのが今まで。
- 各画面の合格条件（ぼくなつの構図の条件）：
  1. 一枚絵として成立している（スクショを人に見せられる）
  2. **どこへ行けるかが一目で分かる**（出入り口が絵の中で読める）
  3. 遠景に抜けがある（山なみ・空・道の先）
- 切替の定石は実装済みのものを維持：入力ラッチ／境界はヒステリシス／90度以上の急変をさせない。

### B. 絵作りはHD-2D式（ライティング＋ポストFX）

1. **舞台照明**：Directional 1灯をやめ、見せ場ごとにスポット/ポイントを置く（縁側の夕方の光、
   土間の囲炉裏、祠の provisions 灯り、木もれ日）。夜・屋内はライトを絞る。
2. **Volume**：DoF（Bokeh・フォーカスは主人公距離・やや深め）＋Bloom（水面・提灯・窓明かり）＋
   Vignette弱＋ColorGrading（純白を使わない・影は青緑）。色収差は演出の瞬間だけ（虫を捕った瞬間など）。
3. **スプライトのライト受け**：主人公・NPCのドット絵に「エミッシブ：ライト受け」比率を持たせ、
   夕方は染まり、囲炉裏では照らされるようにする（ライブアライブ方式）。
4. 罠：Render Scale 100%固定・FXAA必須（7%落としただけでドットが劣化する）。
5. トーンの再調合：HD-2Dはレシピでなく再調合（ライブアライブの教訓）。この作品は「思い出補正された
   日本の夏」なので、DoFやや深め・Bloom強め・コントラスト高めから始めて実写ビルドで詰める。

### C. 地形は「引力と三角形」で増築する（作り直さない）

- **登ると次が見える連鎖**：高台・火の見やぐら・大木など「登れる場所」から、次のランドマーク
  （祠の鳥居・駄菓子屋ののれん・川の光）が1〜2個見えるように地形と配置を調整。
- 目的地は**徐々に**見せる：家から祠が「屋根だけちらっと」見えるように中三角形（丘・木立）で遮蔽。
- 引力源は「行くと得する」で裏打ちする（ぬしの居場所・レア虫の木・涼しい木陰）——経済は実装済みなので
  見え方だけの問題。
- 将来の100画面級への拡張もこの原則で：**地名・見せ場カメラ・道の接続をデータで持つ**（PLAN.mdの覚えの通り）。

## 3. キャラの段階計画（最終形の判断は保留のまま進められる）

DESIGN.md §4-b の最終狙いは「リアル寄りの背景の中を歩く**3D東方キャラ**」。一方いまはドット絵8方向。
どちらに転んでも無駄にならない順で進める：

- **段階1（すぐ）**：ドット絵のまま、ライト受け＋接地影の改良（B-3）。コストほぼゼロ。
- **段階2（試作）**：**3Dトゥーンキャラを1体だけ**作って同じ画面に立たせ、見比べる。
  Xrd式の要点だけの最小構成：UTS3 か lilToon＋法線編集（球転写）＋**コマ打ち（12〜15fps）**＋背面法の線。
  「コマを落とすだけで一気に2Dに見える」が最安の一手なので、モデルの質より先にコマ打ちを検証する。
- **段階3（判断）**：段階2の絵を見て、ドット絵続行か3D移行かを本人が決める。
  ※東方キャラの3Dモデルの入手・権利は本人の領分（こちらからは動かない）。
  試作はプレースホルダ人形（自作 or CC0素体）でやれば権利問題なく判断材料が作れる。

## 4. フェーズと検証（1機能ずつ・実ビルドで撮る、はいつも通り）

| フェーズ | やること | 検証 |
|---|---|---|
| **P0 ものさし** | 目線高さ（子ども1.2〜1.4m相当）・歩速・「村の直径=歩いて何秒」・1日26分から引力源の密度を数値で決めて DECISIONS.md に書く | 数値表が出ること |
| **P1 見せ場カメラ10枚** | 谷・家のまえ・縁側・土間・川べり・祠・駄菓子屋・高台・山道・畑 の10か所に固定構図カメラを設計。合格条件3つ（§2-A）でセルフチェック | `shot.ps1 -cam` で10枚撮って並べる |
| **P2 光とポストFX** | 舞台照明＋Volume＋スプライトのライト受け | 朝/昼/夕/夜×3か所の実ビルド撮影で前後比較 |
| **P3 引力の連鎖** | 高台から次が見える調整・目標の段階遮蔽・変わり種2〜3個 | 高台からのスクショに次のランドマークが写っていること |

P1とP2が「はりぼて・カメラおかしい」への直接の答えなので先頭。P0は半日で終わる前提の下ごしらえ。

## 5. 判断が要るところ（本人と決めたい）

1. **カメラの振り切り度**：完全固定カット割り（ぼくなつ原理主義）まで行くか、
   いまの「追従＋ゾーン」を残して見せ場だけ固定にするか。
   → 草案は後者（追従を残しつつ、ゾーンごとに構図を設計）。理由：地つづきの3Dが売りの企画だから。
2. **キャラの最終形**：ドット絵継続か、3Dトゥーンへの移行か。→ P4の比較スクショを見てから決める、を提案。
3. **背景の最終形**：3Dシーンを磨いて「絵」に見せる（HD-2D路線）か、
   3Dで組んでから2D一枚絵に起こす（ぼくなつ/オラ夏の実フロー）か。
   → 草案は前者。理由：2Dに起こす画力・生成手段が現状ない（実写背景で一度詰まった経緯）。
   ただし「3Dで組む→カメラを決める」までは両路線で共通なので、P1は どちらに転んでも無駄にならない。
4. **着手順**：P1（カメラ）とP2（光）どちらから始めるか。→ 草案はP1から。構図が決まらないと
   照明の置き場も決まらないため（カメラとレベルは同時に設計、の原則）。
